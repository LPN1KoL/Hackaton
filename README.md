# Озеленение по генплану — ЛЦТ 2026, кейс 03

Сервис принимает генплан в DXF (и необязательно геоподоснову) и возвращает тот же чертёж с планом посадок на отдельных слоях `Greening_*`. Исходные слои не меняются. К каждой посадке прилагается обоснование со ссылкой на нормативный акт и пункт.

## Как это работает

```
DXF ─► разметка ─► структуры ─► подбор растений ─► рассадка ─► DXF + обоснования
      (greening)   (blocks)     (recommend: LLM      (place)
                                 или rules)
```

1. **Разметка** (`greening/reader.py`, `surfaces.py`, `sections.py`). Читаются все объекты, включая вложенные блоки, и по `config/layers.json` раскладываются по классам: сети, здания, бортовой камень, покрытия, деревья. Территория строится по «Границе работ», поверхности — по штриховкам и подписям. Газон режется на **секции** нормативными буферами из `config/norms.json`:
   - 743-ПП, табл. 3.6.1 — отступы деревьев и кустарников от сетей, стен, проезжей части, тротуаров, опор;
   - СП 42.13330, табл. 9.1 — коллекторы;
   - 623-ПП (МГСН 1.02-02), п. 4.12.7.3 — детские площадки;
   - ПП РФ № 160 — охранная зона ВЛ.

   У каждой секции есть список того, что в ней разрешено (деревья / кустарники / травянистые), и список сработавших норм. Выноски и стрелки подписей на слоях сетей не дают отступов (`leaders.py`).
2. **Структуры** (`blocks.py`). Территория без проезжей части и зданий, разрезанная по перешейкам уже 6 м. Получаются двор, сквер, бульвар, полоса вдоль улицы — целиком, вместе с дорожками. Внутри структуры — газоны, в газонах — зоны по разрешённым посадкам.
3. **Подбор растений** (`recommend.py`). Для каждой структуры LLM (OpenAI-совместимый API) получает описание места, зоны с условиями и нормами и справочник растений (`config/plants.txt`, 370 видов). Она подбирает единый ассортимент и объясняет каждую зону. Код проверяет ответ: вид есть в справочнике, группа разрешена в зоне, нет широкой кроны у здания, нет ядовитых и колючих у площадок. Без ключа LLM или без сети подбор делают правила (`rules.py`): прогон не зависит от интернета.
4. **Рассадка** (`place.py`). Растения ставятся только в зоны, где их группа разрешена, то есть за нормативными отступами. Сверх норм соблюдаются правила рассадки (`config/placement.json`): расстояния по кроне, отступ от существующих деревьев, шаг ряда. `verify()` независимо проверяет результат.
5. **Выход** (`service.py`). Исходный DXF плюс слои `Greening_Деревья`, `Greening_Кустарники`, `Greening_Цветники`, `Greening_Газон`, а также `justification.json` — обоснование по каждой посадке и зоне (то же, что в карточках просмотра) и `plan.json` — полный план подбора.

**Обоснование каждой посадки** (`plan.json`, поле `plantings`):
- `reason` — текст LLM (или правил): польза, уход, эстетика;
- `norms` — код по данным зоны, например «Отступы для деревьев соблюдены: силовой кабель 2 м, водопровод 2 м (743-ПП, табл. 3.6.1)», «Широкая крона: до зданий 16,5 м, не ближе 10 м соблюдено (743-ПП, табл. 3.6.1, примечание)»;
- `facts` — свойства по справочнику;
- `warnings` — где текст LLM противоречит справочнику.

Отклонённые посадки — в `rejected`, с причиной и нормой. У каждой зоны есть `blocked_by`: какие нормы и на какой доле площади закрыли деревья и кустарники.

## Запуск

### Docker (рекомендуется)

```bash
docker compose up -d --build
```

Ключ LLM необязателен: заполните `.env` в корне репозитория (см. шаг 2 локального запуска), без него растения подбираются правилами.

Сервис откроется на `http://<адрес машины>/` (порт 80, nginx). Загрузите генплан (и, если есть, геоподоснову) и дождитесь обработки: новый генплан — 1–5 минут. Затем откройте просмотр или скачайте DXF и обоснование.

Прогон из командной строки (папка `./data` монтируется в контейнер как `/data`):

```bash
docker compose run --rm greening python -m greening.service /data/Генплан.dxf --geobase /data/Геоподоснова.dxf --out /data/result
# --no-llm   — подбор растений правилами, без сети
# --seed N   — другой вариант случайной рассадки
# --limit N  — в LLM только N крупнейших структур
```

Результат в `data/result/`: `result.dxf`, `justification.json` (обоснования), `plan.json` (план подбора), `placement.geojson` (точки посадок), `summary.json`.

### Локальный запуск (без Docker)

Нужен Python 3.13 и 8 ГБ памяти (для крупных генпланов — больше). Все команды — из корня репозитория.

**1. Окружение и зависимости**

Windows (PowerShell):

```powershell
python -m venv venv
venv\Scripts\pip install -r requirements.txt
$env:PYTHONIOENCODING = "utf-8"   # иначе консоль cp1251 не выведет справку и журнал
```

Linux / macOS:

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

Дальше примеры для Windows; в Linux вместо `venv\Scripts\python` — `venv/bin/python`.

**2. Ключ LLM (необязательно)**

Создайте в корне репозитория файл `.env`:

```
BASE_URL=https://адрес-api/v1
API_KEY=ваш-ключ
# необязательно:
# LLM_MODEL=модель
# SUB_BASE_URL=, SUB_API_KEY=, SUB_MODEL= — запасная модель (адрес и ключ по умолчанию — основные)
```

API должен быть OpenAI-совместимым. Без `.env` или с `--no-llm` / `GREENING_LLM=0` растения подбираются правилами, сеть не нужна.

**3. Веб-интерфейс**

```powershell
venv\Scripts\python manage.py runserver 127.0.0.1:8080 --noreload
```

Откройте `http://127.0.0.1:8080/`, загрузите генплан (и, если есть, геоподоснову). Задачи и результаты сохраняются в `jobs/`, ответы LLM кэшируются в `.llm_cache/`. Сервер запущен без автоперезагрузки: после правок кода его нужно перезапустить. База данных сервису не нужна, `migrate` выполнять не обязательно.

Проверка без LLM:

```powershell
$env:GREENING_LLM = "0"; venv\Scripts\python manage.py runserver 127.0.0.1:8080 --noreload
```

**4. Командная строка**

Весь конвейер одним вызовом:

```powershell
venv\Scripts\python -m greening.service data\Генплан.dxf --geobase data\Геоподоснова.dxf --out data\result
```

| Параметр | Что делает |
|---|---|
| `--geobase ФАЙЛ` | геоподоснова (необязательно) |
| `--out ПАПКА` | папка результата (по умолчанию `<имя>.result` рядом с генпланом) |
| `--no-llm` | подбор растений правилами, без сети |
| `--limit N` | в LLM — только N крупнейших структур |
| `--seed N` | другой вариант случайной рассадки |
| `--cache ПАПКА` | кэш ответов LLM (по умолчанию `.llm_cache`) |

Результат: `result.dxf`, `justification.json`, `plan.json`, `placement.geojson`, `summary.json`, `view.json`.

Отдельные шаги конвейера:

```powershell
venv\Scripts\python -m greening data\Генплан.dxf --geobase data\Геоподоснова.dxf --out out           # разметка → *.greening.geojson, *.greening.dxf
venv\Scripts\python -m greening.recommend out\Генплан.greening.geojson                                 # подбор растений → *.plan.json
venv\Scripts\python -m greening.place out\Генплан.greening.geojson out\Генплан.plan.json --seed 1      # рассадка → *.placement.geojson/.dxf
venv\Scripts\python -m greening.split out\Генплан.greening.geojson --plan out\Генплан.plan.json        # DXF + JSON на каждую структуру
```

**5. Тесты**

```powershell
venv\Scripts\python -m unittest discover greening/tests
```

### API

Swagger — `/docs/`. Как пользоваться:
- `POST /upload/` (`file`, необязательно `geobase`) → `202 {job}`;
- `GET /jobs/{job}/` — этап и ход обработки;
- `GET /jobs/{job}/dxf/`, `…/report/` (обоснование), `…/plan/`, `…/placement/`, `…/view/` — результаты.

## Интерфейс

Загрузка → обработка (этапы, счётчик структур) → результат (сводка, скачивание DXF и обоснования) → просмотр:
- **чекбоксы слоёв:** покрытия, зоны «что можно сажать», газон, цветники, границы, существующие и новые деревья и кустарники;
- **список структур;**
- **объяснение каждой посадки и зоны.** Клик по растению на карте открывает его обоснование.

## Настройки

- `greening/config/norms.json` — нормативные отступы и условия места;
- `greening/config/layers.json` — классы слоёв и подписей;
- `greening/config/placement.json` — правила рассадки (параметры модуля, не нормы);
- `config/settings.py` и переменные окружения:
  - `GREENING_LLM=0` — без LLM;
  - `GREENING_LLM_WORKERS` — сколько запросов к LLM идёт параллельно (по умолчанию 5);
  - `GREENING_JOB_ABANDON_S` — через сколько секунд без опроса статуса задача считается брошенной (180);
  - `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_DEBUG` — настройки Django;
  - `GREENING_LLM_LIMIT` в `config/settings.py` — сколько структур отправлять в LLM (не переменная окружения).

## Ограничения

- **Подоснова должна быть внутри DXF.** Внешние ссылки на `.dwg` не читаются: без них нет сетей и покрытий.
- **ВЛ считается напряжением до 1 кВ,** охранная зона теплосети (приказ Минстроя № 197) не учтена.
- **Из 623-ПП (МГСН 1.02-02) применяется только отступ от детских площадок;** в обоснованиях он подписан как «МГСН 1.02.02, п. 4.12.7.3». Ассортимент растений ссылается на справочник без пункта акта.
- **Обоснование дано на посадку-группу,** а не на каждую точку.
- **Время и стоимость:** большой генплан (Олимпийская деревня) обрабатывается десятки минут и требует нескольких гигабайт памяти. LLM тратит около 0,2–0,3 млн токенов на генплан среднего размера; повторный прогон того же чертежа берётся из кэша.
